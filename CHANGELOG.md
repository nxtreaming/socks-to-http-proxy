# Changelog

## 0.9.9

- Add `POST /stats/add` and `--stats-sync-from` so a running instance can import another server's `GET /stats` counters as a watermark sync: repeating the same (or growing) old totals only adds the positive delta. Use this during DNS cutover so traffic that still lands on the old IP continues to appear on the new instance. If the old host is down, sync failures do not change local counters; retries back off after a few misses.
- Watermark sync persists the expected file first, then commits the in-memory delta. A write failure of that first file leaves live counters unchanged and is the only persist error returned to `/stats/reset` and `/stats/add`. After commit, one follow-up snapshot captures bytes that arrived during the first write; traffic during that follow-up is after the linearization point and is left to the next periodic save. Follow-up write errors are logged and do not turn an already-committed reset/add into HTTP 500. `GET /stats` `epoch` is a counter generation: new on process start (not restored from the stats file) and incremented on `/stats/reset`. `GET /stats` returns `rx`/`tx`/`epoch` from one generation snapshot. A source epoch change resets both watermarks and retires the previous generation so delayed samples cannot reactivate it. At most 32 retired generations are kept (never evicted), including when loading a stats file written by an earlier build; further unknown epochs are ignored instead of adopted. `POST /stats/add` requires proxy auth when `--http-basic` is enabled, and otherwise accepts only loopback clients. `epoch` 0 is treated as unknown/legacy. A lower rx/tx with the same epoch is treated as a stale sample and ignored. Reset and sync share the same per-port save lock.
- `GET /stats`, `POST /stats/add`, and `POST /stats/reset` share one local-target check: origin-form is always local; loopback and the specific listen IP are local. Binding `0.0.0.0`/`::` does not treat arbitrary IP literals as local; those scrapers need `--stats-host`. Remote stats bodies are size- and time-limited; DNS lookup for `--stats-sync-from` uses the same I/O timeout as connect and HTTP. `/stats/reset` keeps the sync watermark and subtracts the pre-write snapshot so proxy bytes that arrive during persist are not discarded.

## 0.9.8

- Serialize per-port traffic stats persistence so periodic saves and `POST /stats/reset` cannot race on the same temporary stats file or overwrite reset results out of order.
- Extra SOCKS listener bind failures are now fatal when `--socks-port` is explicitly configured, preventing the process from continuing in a half-ready HTTP-only state.
- Normalize non-CONNECT HTTP forwarding: only `http://...` absolute-form requests are accepted, `https://...` requests are rejected with 400 and should use CONNECT, accepted HTTP request targets are rewritten to origin-form before forwarding upstream, and Host is preserved or synthesized from the original authority when absent.
- Validate `--allowed-domains` entries at startup using the existing domain pattern validator. Patterns are now trimmed and lowercased before storage, and invalid or empty entries fail fast instead of silently never matching.
- Security/behavior change: `--http-basic user:pass` now enables HTTP proxy authentication by default. In earlier versions, credentials were accepted but authentication stayed disabled unless `--no-httpauth=0` was also provided. Existing deployments that intentionally keep HTTP auth disabled while passing credentials must now set `--no-httpauth=1` explicitly.
